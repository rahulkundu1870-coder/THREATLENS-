1.Introduction

ThreatLens is a static file security analyser built entirely in Python using the Streamlit web framework. It is designed as a beginner-friendly cybersecurity dashboard that allows a user to upload any file and immediately receive a detailed threat assessment — without ever executing the file or transmitting it to an external server.

The project is composed of two tools that complement each other. The main application (app.py) performs multi-layer static analysis and correlates indicators into a risk score through a custom Threat Indicator Correlation Engine (TICE). The companion tool (evidence_tool/) focuses specifically on SHA-256 hash verification for digital evidence integrity — a foundational technique in digital forensics.

Core principle: ThreatLens inspects raw bytes only. No file is executed at any point. Analysis is performed entirely in memory; files are never written to disk.

2.Problem Statement

Modern cyber threats increasingly rely on disguising malicious files as benign ones. Common attack vectors include executable files hidden behind innocent-looking extensions (e.g. a Windows PE binary renamed to photo.jpg), scripts with double extensions (e.g. invoice.pdf.exe), and payloads obfuscated through encryption or packing to evade signature-based detection.

Traditional antivirus tools require large signature databases, constant internet connectivity, and opaque detection logic that provides little educational value. There is a clear need for a transparent, locally-running tool that demonstrates exactly why a file is considered suspicious — showing every triggered rule and its contribution to the final risk score.

4.Background & Core Concepts

4.1 SHA-256 Cryptographic Hashing

SHA-256 (Secure Hash Algorithm, 256-bit output) is a member of the SHA-2 family standardised by NIST in FIPS PUB 180-4 (2015). It converts any input — regardless of size — into a fixed 64-character hexadecimal string. Its three key properties make it central to both tools in this project:

PropertyMeaningRelevance
DeterminismSame input → always same outputReliable file fingerprinting
Avalanche effectOne byte change → completely different hashDetects any tampering
One-way functionCannot recover file from hashSafe to share hashes publicly
Collision resistanceInfeasible to find two files with the same hashHash uniquely identifies a file

4.2 Magic Bytes (File Signature Analysis)

Every file format defines a specific byte sequence at the beginning of the file, known as a magic number or file signature. For example, all Windows PE executables begin with the bytes 4D 5A ("MZ"), while JPEG images begin with FF D8 FF. ThreatLens compares the first bytes of any uploaded file against 16 known signatures to determine its true type — independent of its filename extension.

4.3 Shannon Entropy

Shannon entropy measures the randomness of a byte sequence on a scale of 0 to 8 bits per byte. Natural language and source code produce entropy below 5.0. Compressed or encrypted data approaches the theoretical maximum of 8.0 because the bytes are nearly uniformly distributed. Malware authors frequently encrypt or pack payloads to evade detection, making very high entropy (> 7.2 bits/byte) a meaningful threat indicator.

4.4 Static Analysis

Static analysis examines a file's content without executing it. Unlike dynamic analysis (running the file in a sandbox), static analysis carries no risk of infection and can be performed instantly on any machine. ThreatLens uses exclusively static techniques, making it safe to run on suspected malicious files.

7.Core Analysis Engine

7.1 SHA-256 Hashing

The sha256_hash(data: bytes) → str function uses Python's built-in hashlib module to produce a 64-character hex digest. This fingerprint is used for identity tracking across sessions and as the input to the known-hash lookup in TICE.

7.2 Magic-Byte Detection

detect_magic(data: bytes) → Optional[str] compares the file's leading bytes against 16 known signatures. The function handles one special case: the MP4/MOV signature (66 74 79 70) can appear at byte offset 4, so that offset is checked explicitly.

7.3 Extension Mismatch Detection

check_extension_mismatch(filename, magic_type) raises a warning when a file's declared extension conflicts with its detected header. Two disguise patterns are specifically checked: an executable header inside an image or document extension, and a ZIP/Office archive pretending to be a PDF or image. This is one of the highest-weighted TICE rules (40 points).

7.4 Shannon Entropy Calculation

calculate_entropy(data: bytes) → float computes the Shannon entropy over the full 256-symbol byte alphabet. The formula used is: 

H = -Σ p(b) × log₂(p(b))   for each byte value b with p(b) > 0

The result is a float in the range 0.0–8.0 bits per byte. Thresholds used for classification: < 5.0 = normal, 5.0–6.5 = elevated, 6.5–7.2 = high, > 7.2 = very high.

7.5 Suspicious String Scanner

find_suspicious_strings(data: bytes) → list decodes the raw bytes using latin-1 (a lossless encoding for arbitrary bytes) and scans for nine categories of malicious patterns:

8.Threat Indicator Correlation Engine (TICE)

TICE is the scoring subsystem that takes all individual indicator results and combines them into a single transparent risk score (0–100). Every fired rule, its point contribution, and its plain-English explanation are shown to the user — there is no black-box decision making.

8.1 Scoring Rules

Rule

Score is capped at 100. Tiered rules are mutually exclusive: only the higher tier fires (e.g. if ≥3 suspicious patterns fire, the "1–2 patterns" rule is suppressed).

8.2 Classification Thresholds

Score RangeClassificationRecommended Action

20 – 49MediumReview flagged indicators manually. Consider sandboxing before opening.
50 – 74HighDo not open. Quarantine and escalate to security team.
75 – 100CriticalImmediate isolation required. Submit to incident response.

8.3 Known-Hash List

TICE maintains a small in-memory hash dictionary (KNOWN_TEST_HASHES) populated at startup from the SHA-256 digests of two fictional sample payloads (dropper.exe and photo_vacation.jpg). This demonstrates hash-based threat intelligence matching — in a production system, this list would be replaced by a live feed from a threat intelligence platform.

9.User Interface & Features

The dashboard uses a custom dark theme (GitHub Dark palette: #0d1117 background, #58a6ff blue accent) implemented via injected CSS. The layout is divided into four clearly separated sections:

SectionDescription
Upload & AnalysisFile uploader, instant result card with risk badge, entropy progress bar, extension risk, mismatch warning, suspicious string list, expandable full hash
Report DownloadPlain-text security report covering all files scanned in the current session
TICE DashboardFour stat cards (files analysed / review / high / critical), findings table, expandable detail view per file, TICE investigation report download
Sample Data LabTen fictional byte payloads; "Generate Sample Data" shows the records table; "Run Security Analysis" executes the full detection pipeline on all ten samples

Session state (st.session_state) is used to persist all counters and scan history across reruns within the same browser session. The dashboard is fully reactive — uploading a new file triggers a st.rerun() to refresh stat cards immediately.

10.Companion Tool — Evidence Integrity Verifier

The evidence_tool/ sub-project is a standalone Streamlit application focused exclusively on SHA-256 file integrity verification — a core technique in digital forensics chain-of-custody documentation.

10.1 Features

10.2 Design Decisions

Hashing logic is isolated in hash_utils.py — a pure Python module with no Streamlit dependency. This separation means the automated tests can import and test the hashing functions without needing a running Streamlit instance. The chunk-based reading strategy (64 KB chunks) ensures the tool handles arbitrarily large files (disk images, video files) without running out of memory while producing the same hash as single-pass reading.

13.Conclusion

ThreatLens successfully demonstrates multiple foundational cybersecurity concepts — cryptographic hashing, binary file analysis, Shannon entropy, and rule-based threat scoring — within a single, locally-running web application. Every decision the system makes is explained to the user in plain English, making the tool valuable as both a practical security aid and a learning resource.

The Threat Indicator Correlation Engine provides a transparent alternative to opaque signature-based scanners: users see every triggered rule, its point contribution, and the exact recommendation that follows from the final score. The companion Evidence Integrity Verifier grounds the project in a real-world forensic workflow, backed by 11 automated tests that prove the correctness of the SHA-256 implementation.

All stated objectives were met. The application is built exclusively from free, open-source tools, processes all data locally, and is designed to be approachable by students with basic Python knowledge.
